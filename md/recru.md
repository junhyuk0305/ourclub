[바이브 코딩용 리크루팅 SaaS 최종 기능 명세서]
0. 시스템 핵심 아키텍처 및 공통 컴포넌트
Data Flow:
Club: 고유 채용 포털 URL 보유
Recruitment: Club당 최대 3개 공고 생성. 마크다운 기반 직무 요강 데이터 보유. 배포 후 수정 가능
Application Form: Recruitment 종속. 커스텀 문항 배열(JSON) 보유
Applicant: 폼 제출 시 생성. 파이프라인 단계(Stage) 및 응답, 평가 데이터 보유
공통 UI 컴포넌트 (Reusable Markdown Component):
마크다운 에디터 및 뷰어를 독립적인 React 컴포넌트(예: <MarkdownEditor />, <MarkdownViewer />)로 모듈화
향후 타 웹페이지 빌더 기능 추가 시 그대로 Import하여 사용할 수 있도록 상태 관리와 UI 렌더링 로직을 완전히 분리
1. 관리자: 공고 설계 및 폼 빌더 (Admin - Full Page Editor)
전체 화면 기반의 작성 경험(Full-page UI):
좁고 답답했던 모달(Modal) 창 폐기. '새 공고 만들기' 또는 '수정' 클릭 시 넓은 작업 공간을 확보한 전용 에디터 페이지로 라우팅
마크다운 기반 모집 요강 에디터:
상단 영역에 독립된 마크다운 컴포넌트 배치. 좌측 입력 / 우측 실시간 프리뷰(Split View) 형태나 Notion 스타일의 Block 에디터 방식 채택
커스텀 지원 폼 빌더:
에디터 하단에 단답형/장문형 문항을 추가하는 폼 빌더 배치
공고 수정 가능:
작성 완료 후 '배포(Publish)' 상태에서도 문항 및 요강 수정가능처리
2. 관리자: 리크루팅 파이프라인 관리 (Admin - Multi-View Board)
뷰 토글링(View Toggle): 우측 상단에 아이콘 버튼을 배치하여 관리자의 목적에 따라 화면 모드 전환
[1] 칸반 뷰 (Kanban View): 기존 방식. 단계별 지원자 카드를 Drag & Drop하여 직관적인 상태 변경 (상태 변경 시 이메일 발송 자동화 모달 연동)
[2] 리스트 뷰 (Table/List View - New): 지원자 전체를 Excel과 같은 표(Data Grid) 형태로 일렬 나열. 이름, 지원일, 현재 단계, 평가 점수 등의 열(Column) 제공. 다중 선택(Checkbox) 및 일괄 상태 변경, 정렬, 필터링에 최적화
데이터 내보내기 (Export): 선택/전체 지원자의 문항별 응답 및 평가 데이터를 CSV/Excel 포맷으로 다운로드
3. 관리자: 지원자 상세 관리 워크스페이스 (Admin - Expanded Detail View)
UI/UX 개선 (여백 확보 및 정보 분산):
기존의 좁은 우측 슬라이딩 드로어(Drawer) 대신, 카드를 클릭하면 화면의 80% 이상을 덮는 넓은 확장형 모달(Extended Modal) 또는 독립된 상세 페이지로 진입
탭(Tab) 기반 UI 레이아웃:
한 화면에 모든 정보(지원서, 메모, 면접 질문)를 욱여넣지 않고 탭으로 분리
[지원서 탭]: 지원자가 제출한 커스텀 응답 내용 원본 확인
[평가 및 메모 탭]: 운영진 점수 입력, 내부 채팅(메모)
[면접 풀(Pool) 탭]: 해당 지원자 전용 질문 리스트업 및 관리
4. 지원자 경험 (Applicant - Portal & Form)
동아리 전용 채용 포털 랜딩:
구인자 고유 URL(/club/{club_id}) 접속 시 현재 모집 중인 배포 상태의 공고(최대 3개) 노출. 내부 채용 프로세스(서류>면접 등)는 지원자에게 블라인드 처리
직무 소개페이지 (Job Description Modal):
리스트에서 '지원하기' 클릭 시 바로 작성 폼으로 넘어가지 않음
관리자가 앞서 작성한 마크다운 데이터가 <MarkdownViewer /> 컴포넌트를 통해 깔끔하게 렌더링된 안내 페이지
직무소개 확인 후, 모달 내 액션 버튼을 통해 실제 폼 작성으로 진입
상태별 컴포넌트 렌더링:
모집 마감 시, 폼 대신 에러/안내 컴포넌트("모집이 마감되었습니다") 렌더링
제출 완료 시 칸반 보드 '접수' 단계로 실시간 동기화(Real-time Insert)
