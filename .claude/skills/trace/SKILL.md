사용자가 보고한 에러/버그를 **근본 원인까지** 추적해줘.

### 분석 순서 (반드시 이 순서로)

**1단계: 에러 파싱**
에러 메시지/증상에서 → 타입, 발생 위치, 발생 조건을 추출

**2단계: 가설 설정**
가능한 원인 3가지를 확률 순으로 나열. 추측이면 명시.

**3단계: 코드 추적**
의심 파일을 직접 Read 툴로 읽어서 실제 코드 확인. (추측으로 답하지 말 것)

**4단계: 근본 원인 확정**
증상이 아닌 실제 원인 한 문장으로. 예: "X 컴포넌트의 useEffect가 session 변경마다 실행되며 Y를 초기화함"

**5단계: 최소 수정**
CLAUDE.md 원칙: 건드려야 하는 코드만 수정. 수정 전/후 코드 비교로 제시.

**6단계: 재발 방지**
같은 패턴의 버그가 다른 곳에도 있는지 확인하고 언급.
